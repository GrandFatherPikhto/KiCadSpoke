# fieldstool — массовая простановка/переименование Role/Cluster в `.kicad_sch`

Отдельное приложение, не часть `kicadstamp`/[PyQt6 GUI](./gui_ru.md): `fieldstool/` (библиотека) +
`fieldstool_cli.py` (CLI) + `fieldstool_gui.py` (GUI). Правит `.kicad_sch` **напрямую, текстом** —
не через живой IPC KiCad — потому что кастомные поля `Role`/`Cluster` живут в схемном символе, а
PCB-only запись через IPC (то, что делает `gui/docks/bulk_field_editor.py`) тихо затирается
собственным «Update PCB from Schematic» KiCad. См. [Почему отдельно](#почему-отдельно) ниже, прежде
чем считать, что это можно было бы сделать ещё одной докой в основном GUI.

## Почему отдельно

- **Принципиально другая, более рискованная зона записи.** `kicadstamp`/`gui` пишут только через
  живой транзакционный IPC KiCad (`BeginCommit`/`UpdateItems`/`EndCommit` — с undo самого KiCad).
  `fieldstool` правит `.kicad_sch` как файл, напрямую — тот же класс риска, что баг KiCad #24966
  (правка файла, который KiCad, возможно, держит открытым/закешированным), но хуже — тут вообще нет
  живого IPC KiCad.
- **KiCad должен быть закрыт для применения, и переоткрыт, чтобы увидеть результат.** Работающий
  процесс KiCad не подхватывает изменённый извне файл схемы «на лету». Проверено исчерпывающе (kipy
  0.7.1): в `kipy.KiCad`, `kipy.Board`, `kipy.Schematic` и во всех определениях proto-команд **нет
  вообще никакого способа программно закрыть KiCad или проверить «есть ли несохранённые
  изменения»**. Значит, кнопка «закрыть KiCad» может быть только **инструкцией** пользователю
  («закрой KiCad, потом жми Apply») — никогда не автоматизацией. Это требование несовместимо с
  моделью основного GUI, который всегда открыт рядом с живым KiCad.
- **Точечная правка, не parse→dump.** Правки — точечная подстановка текста (regex + баланс скобок
  для границ блоков), никогда не полный цикл `sexpdata` parse→`dumps()` — нет прецедента, что
  `sexpdata.dumps()` воспроизводит форматирование самого KiCad побайтово. `sexpdata` используется
  только для **самопроверки** результата после записи (см. [Страховки](#страховки)).

## `fieldstool_cli.py`

```bash
python fieldstool_cli.py set roles.yaml [--write] [--allow-non-ascii] [--force-with-kicad-running] [--verbose]
python fieldstool_cli.py rename renames.yaml [--write] [--allow-non-ascii] [--force-with-kicad-running] [--verbose]
```

Оба подкоманды по умолчанию dry-run (печатают, что изменится, ничего не трогают); `--write`
обязателен, чтобы реально что-то поправить.

### `set` — refdes → `{field: value}`

```yaml
root_sheet: ../test_boards/3CH-AWG-TIA/3CH-AWG-TIA.kicad_sch   # КОРНЕВОЙ лист проекта, не папка
fields:
  C51:
    Role: C_OUT_BULK
    Cluster: FPGA_PWR_BANK/17
  C52:
    Role: C_OUT_BULK
    Cluster: FPGA_PWR_BANK/26
```

`root_sheet:` обходится рекурсивно (ссылки `(sheet (property "Sheetfile" "...") ...)`, безопасно
при ромбах/циклах), чтобы найти каждый достижимый `.kicad_sch` — не плоский glob по директории, так
что случайный посторонний `.kicad_sch` в той же папке никогда не попадёт в обработку по ошибке.

Два способа, которыми один refdes встречается в файле, оба учтены:
- **Многоюнитовый символ** (например, сдвоенный ОУ) — один refdes сидит в нескольких отдельных
  `(symbol ...)` блоках (по одному на unit); правятся все.
- **Многократный инстанс одного листа** (например, `Channel_1`/`2`/`3`, все — инстансы одного
  `channel_tpl.kicad_sch`) — несколько refdes делят ОДИН `(symbol ...)` блок, поле общее для всех
  них. Если конфиг просит **разные** значения для двух таких refdes — формат физически не может
  это выразить: фатальный отказ, а не молчаливый выбор одного из двух.

### `rename` — `field → {old_value: new_value}`, без refdes

```yaml
root_sheet: ../test_boards/3CH-AWG-TIA/3CH-AWG-TIA.kicad_sch
renames:
  Role:
    OLD_ROLE_A: NEW_ROLE_A
  Cluster:
    Old_Cluster_Name: New_Cluster_Name
```

Меняет значение везде, где оно СЕЙЧАС встречается, по всей иерархии схемы — перечислять затронутые
refdes не нужно. Проще `set` в одном отношении: конфликт многократного инстанса тут в принципе
невозможен, поскольку во все совпадения всегда пишется одно и то же новое значение. `old_value`, не
совпавший нигде, репортится как **предупреждение**, не фатал — это с равной вероятностью безобидный
повторный запуск (переименование идемпотентно), как и опечатка.

### Страховки

- **Dry-run по умолчанию** — `--write` обязателен, чтобы что-то тронуть.
- **`.bak` + самопроверка на каждый файл, независимо** — перед записью исходный текст копируется в
  `<file>.bak`; после подстановки результат перепарсивается через `sexpdata` как проверка. Если не
  парсится — файл восстанавливается из `.bak` и репортится как неудачный, остальные файлы в пачке
  всё равно обрабатываются.
- **Отказ при не-ASCII** (`--allow-non-ascii` для обхода) — страхует ровно тот класс
  опечатки-гомоглифа, из-за которого этот инструмент вообще появился (кириллическая «С» вместо
  латинской в значении `Role`).
- **Отказ при запущенном KiCad** (`--force-with-kicad-running` для обхода) — `.kicad_sch`, открытый
  в Eeschema, рискует получить правку, которая будет тихо затёрта следующим сохранением из KiCad.
- После `--write` обязательно **«Update PCB from Schematic» в pcbnew** — правка сама на плату не
  долетает.

## `fieldstool_gui.py`

```bash
python fieldstool_gui.py [--timeout-ms 20000] [--verbose]
```

Разбивает workflow на две фазы с разными требованиями к KiCad, в соответствии с ограничением выше:

### 1. Staging (KiCad открыт)

- **Pick root sheet** — указывает инструменту на проект (тот же концепт `root_sheet:`, что у CLI).
  **Rescan** перепарсивает (явное действие, не автополлинг — схема меняется только когда кто-то
  сохраняет в Eeschema, не каждые пару секунд).
- **Дерево компонентов** — тот же UX, что [дерево компонентов](./gui_ru.md#дерево-компонентов)
  основного GUI (группировка по Role/Cluster, фильтр с опциональным regex), но построено из
  РАСПАРСЕННОЙ схемы, не из живого PCB-снапшота. Одна строка на refdes (общий многоинстансный блок
  разворачивается в одну строку на каждого участника; многоюнитовый refdes схлопывается в одну
  строку, помечается ⚠, если его units расходятся по Role/Cluster — схема это допускает, ничего не
  гарантирует синхронность).
- **Выбор цели** — три взаимозаменяемых способа, все кормят одну и ту же форму редактирования:
  - клик по **листу** дерева (один refdes),
  - клик по узлу-**группе** (сразу все refdes этой группы Role/Cluster — так делается «переименовать
    целую группу» без перепечатывания refdes),
  - или просто **выделить что-то в самом KiCad** (в Eeschema ИЛИ в Pcbnew — живое read-only
    соединение следит за выделением на PCB, а поскольку выделение на схеме и плате в KiCad
    кросс-пробируются, выделение со стороны схемы тоже сюда долетает).
- **Stage** — записывает текущие значения формы Role/Cluster в JSON-очередь отложенных изменений,
  по одной записи на целевой refdes. `.kicad_sch` пока не тронут. Очередь персистится (`<root
  sheet>.pending.json`, рядом со схемой) — можно закрыть GUI и вернуться позже.

### 2. Apply (KiCad должен быть закрыт)

- Проверяет, не запущен ли KiCad — если да, показывает **инструкцию** («сохрани работу и закрой
  KiCad, потом снова жми Apply»). Никогда не автоматизируется (см.
  [Почему отдельно](#почему-отдельно)).
- Если KiCad закрыт: прогоняет каждую отложенную правку через тот же самый офлайн-пайплайн, что
  использует `fieldstool_cli.py set`, показывает сводку для подтверждения, затем пишет (те же
  страховки `.bak`/самопроверка, что у CLI). При успехе очередь очищается, дерево перестраивается.

## Перенесено из `tools/apply_role_cluster.py`

`fieldstool set` заменяет этот скрипт (перенесён и обобщён 2026-08-01, не оставлен дублирующимся)
— та же основная логика (парсинг, точечная запись, страховки), просто реорганизована в переиспользуемую
библиотеку плюс режим `rename`, которого там не было. `root_sheet:` (обход иерархии) заменяет
`schematic_dir:` (плоский glob) — **не обратно совместимо**, старые конфиги нужно обновить.
